# 공모전 규칙과 Pleos SDK 조사

아이디어를 정하기 전에 공모전 규칙과 실제로 쓸 수 있는 Pleos API를 정리한 문서입니다. 2026-11-01에 [공모전 사이트](https://appdevchallenge.auto-hmg.io/guide)와 [Pleos Connect 개발자 가이드](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/)를 읽고, Windows의 Pleos Connect Emulator 2.1.0에서 확인했습니다. 규정은 바뀔 수 있으니 제출 전에 원문을 다시 확인하세요.

## 핵심 요약

- **접수 마감은 2026-11-15(일)입니다.** 필수 제출물은 접수양식(기획서) 하나이고, 시연 영상·GitHub 저장소·APK를 함께 내면 단계별 가산점을 받습니다.
- **1차 합격 20팀은 2026-12-03~04 PT 심사에서 실제로 동작하는 앱을 시연해야 합니다.** 에뮬레이터 시연도 인정됩니다.
- **지금 신청 없이 쓸 수 있는 SDK는 Vehicle State와 NaviHelper뿐입니다.** FusedLocation, TextToSpeech, SpeechToText, Vehicle Control은 Playground에서 "준비 중"으로 안내됩니다. 공모전 사이트는 다섯 SDK를 모두 쓸 수 있다고 소개하므로 확인이 필요합니다.
- **주행 중에는 앱 사용이 기본적으로 막힙니다.** Distraction Optimization(DO)을 선언하지 않은 앱은 주차 중에만 사용할 수 있습니다. 아이디어를 정할 때 "주행 중에 어떻게 보이고 조작되는가"를 먼저 정해야 합니다.

## 참가와 제출

- **참가 자격**: 대학(원)생·일반인·스타트업, 개인 또는 최대 5인 팀. 시상 부문은 대학생과 일반(스타트업 포함)으로 나뉩니다.
- **접수 방법**: 접수양식(기획서)과 개인정보 동의서를 `appdevchallenge@hyundai-partners.com`으로 보냅니다. 팀원 전원이 각자 동의서에 서명하고, 대표자가 팀원 전원을 CC에 넣습니다.

  - 수정 제출 제목: `[수정제출] [차량용 앱 개발 공모전] 팀명_대표자명`. 전체 자료와 서명한 동의서를 모두 다시 첨부합니다. 마감 전 마지막 제출본으로 심사합니다.
- **접수양식 5번(개발 계획)** 에는 Pleos Connect에서 어떻게 구현할지, 주요 개발 범위와 SDK/API 사용 계획을 구체적으로 적습니다.

- APK는 저장소의 `apk/` 폴더에 `팀명_앱이름_release.apk` 이름으로 올립니다. **release 빌드**여야 하고, 용량이 크면 GitHub Releases에 올리고 그 링크를 냅니다.
- 이 저장소처럼 비공개 저장소도 제출할 수 있습니다. 공지된 심사용 GitHub 계정을 Collaborator로 초대하고, 마감 전에 그 계정으로 접근되는지 확인합니다. 개인 계정의 비공개 저장소는 Collaborator에게 쓰기 권한까지 주어진다는 점에 유의합니다.
- README.md에는 앱 이름과 한 줄 소개, 실행 방법, 테스트 환경과 필요한 설정, APK 위치 또는 Release 링크를 적습니다.

## 심사 기준

1차 서류심사는 네 항목을 필수로 평가하며 세부 배점은 공개하지 않습니다. 2차 PT 심사 기준은 추후 공지 예정입니다.

| 항목 | 평가 내용 | 기획할 때 확인할 질문 |
| --- | --- | --- |
| 차량특화성 | 모바일보다 차량 환경에서 더 가치가 있는가, 주행·정차 맥락과 차량 기능에 결합되었는가 | 휴대폰 앱으로도 똑같이 되는가? 그렇다면 감점 요인 |
| 창의성 | 독창적인가, 운전자·동승자의 Pain Point와 해결 방식이 명확한가 | 누구의 어떤 불편을 푸는지 한 문장으로 말할 수 있는가? |
| 기술 활용성 | Playground의 SDK·API를 핵심 기능에 적절히 활용했는가 | SDK를 빼면 앱이 성립하지 않는가? |
| 사업성 | 타깃 고객, 예상 MAU, 리텐션, 확장 계획이 있는가 | 다시 쓸 이유가 있는가? |

공모전 사이트가 예로 든 주제는 모빌리티·라이프 편의, 인카 엔터테인먼트, 스마트 드라이빙·안전, 패밀리·동승자 케어입니다. 예시 앱은 음성 메모, 안전운전 점수, 배달 기사용 앱이며, 주제를 제한하지는 않습니다.

## Pleos Connect SDK

### SDK별 제공 상태

| SDK (가이드 기준 버전) | 주요 기능 | Playground 상태 | 에뮬레이터 서비스 | 비고 |
| --- | --- | --- | --- | --- |
| Vehicle (2.3.2) | 차량 상태 조회·구독, 일부 제어 | **사용 가능** (State) | `VehicleService` 실행 중, 샘플 앱 연결 확인 | 제어(Vehicle Control)는 준비 중 |
| NaviHelper (3.0.5) | 목적지·경유지 설정, 경로 옵션, 주행 이벤트 수신 | **사용 가능** | `NaviService` 실행 중 | 내비게이션 탑재 차량만 지원 |
| TextToSpeech (3.3.1) | 음성 합성 후 차량 스피커 재생 | 준비 중 | `SpeechService`(CaaS) 실행 중 | ON_DEVICE 모드는 앱 등록 불필요 |
| SpeechToText (3.3.1) | 음성을 텍스트로 변환 (명령 실행은 안 함) | 준비 중 | `SpeechService`(CaaS) 실행 중 | ON_DEVICE 모드는 앱 등록 불필요 |
| FusedLocation (1.1.3) | 차량 위치, 위치 업데이트, 지역 진입·이탈 알림 | 준비 중 | 패키지 설치됨 | `isSupported()`로 지원 확인 필요 |

"Playground 상태"는 [프로젝트 생성 및 SDK 사용 신청](https://document.pleos.ai/docs/pleos-only/create-my-project) 문서 기준입니다. "에뮬레이터 서비스"는 서비스가 설치되어 실행 중인지만 본 것이고, TTS·STT·FusedLocation API를 실제로 호출해 보지는 않았습니다.

### Vehicle SDK 도메인

Vehicle 객체에서 `getDoor()`, `getHvac()` 같은 메서드로 도메인 객체를 얻습니다. 각 도메인은 capability(지원 여부), get(현재 값), set(설정), callback(상태 변화 구독) API를 제공하며, 결과는 모두 비동기 콜백으로 옵니다.

| 도메인 | 내용 | 조회 권한 |
| --- | --- | --- |
| Brake, DrivingMode, Odometer | 브레이크 페달·주차 브레이크, 드라이브 모드·크루즈, 주행 거리·트립 | `CAR_DRIVE` |
| CarInfo, Display | 차량 기본 정보, 표시 단위 | `CAR_INFO` |
| Door | 도어 열림·잠금 | `CAR_DOORS` |
| EvBattery, Fuel | 배터리·충전 상태와 전비, 연비 | `CAR_ENERGY` |
| HVAC | 온도, 풍량, 습도 등 공조 | `CAR_CLIMATE` |
| Light, TurnSignal | 조명·앰비언트 라이트, 방향 지시등 | `CAR_LIGHTS` |
| Safety, Tire | 차량 경고, 타이어 상태 | `CAR_SAFETY` |
| Seat | 좌석 위치·열선·통풍 | `CAR_SEATS` |
| SideMirror, Steeringwheel | 미러 열선, 핸들 상태·열선 | `CAR_MIRRORS` 등 |
| Toll | 하이패스(ETCS) | `CAR_TOLL` |
| Window, Wiper | 창문, 와이퍼 | `CAR_WINDOWS` |

- 매니페스트에는 `pleos.car.permission.CAR_*` 형식으로 선언합니다. 조회는 `CAR_*`, 제어는 `CONTROL_CAR_*` 권한이 필요합니다.
- 권한은 **Pleos App Market과 사전 협의·승인된 범위에서만** 쓸 수 있고, 승인되지 않은 권한을 선언하면 앱 심사를 통과할 수 없습니다. Vehicle Control은 아직 준비 중이므로, 핵심 기능은 **차량 상태 조회** 위주로 설계하는 편이 안전합니다.
- 실제 차량에서는 모델마다 지원 기능이 다르므로 `checkXXXCapabilities`로 확인한 뒤 분기합니다.

### Virtual Console로 흉내 낼 수 있는 신호

시연 영상과 PT 심사에서 상황을 연출할 때 씁니다. `adb forward tcp:8088 tcp:8088` 후 `http://127.0.0.1:8088/`에서 조작합니다.

- **주행**: 기어(P/R/N/D), 가속·브레이크 페달, 조향각, 크루즈 상태·목표 속도, 주차 브레이크
- **에너지**: 배터리 SOC·에너지·용량, 남은 주행 거리, 충전 스위치·충전구·충전 제한, 주행 거리
- **차체**: 도어 열림·잠금, 트렁크·프렁크, 창문 위치·잠금, 좌석 착석 여부, 와이퍼, 글러브박스
- **공조**: 전원, A/C, 오토, 내외기, 풍량·풍향, 성에 제거, 목표 온도, 시트 열선·통풍, 핸들 열선, 공기청정
- **조명**: 실내등·독서등, 앰비언트 밝기·색상, 전조등·상향등·비상등·브레이크등, 방향 지시등
- **경고등(Telltale)**: 안전벨트, 도어 열림, TPMS, 엔진 온도, 저전압 배터리, 에어백 등 30여 종
- **기타**: 하이패스(진입·진출·카드 삽입), 알림 표시

## 주행 규제와 앱 설계

- DO를 선언하지 않은 앱은 **주차 중에만** 사용할 수 있고 주행 중에는 사용할 수 없습니다.
- 주행 중 규제 상태에서는 키보드, 동영상, 차량 설정, 긴 텍스트가 제한됩니다. 북미는 검색도 음성으로만 가능합니다. 앱은 `CarUxRestrictions`로 현재 제한 상태를 확인하고 해당 UI를 줄이거나 꺼야 합니다.
- 주행 중 일부 기능이 허용되는 카테고리는 Music/Audio, Maps/Navigation, Mobility Services(충전소·주유소·주차장 찾기, 차량 관리 등)입니다.
- 설계 원칙: 한눈에 이해되는 정보, 큰 터치 영역과 높은 대비, 텍스트 입력 대신 프리셋·최근 항목·음성 우선, 움직이는 시각 요소 최소화.

차량특화성과 주행 규제를 함께 고려하면, 아이디어는 다음 중 하나에 걸치는 것이 유리합니다.

1. **정차·주차·충전 중**에 쓰는 앱 (충전 대기, 주차 중 휴식, 차박, 동승자 케어 등)
2. **주행 중에는 음성이나 한눈에 보는 정보만** 주는 앱 (안전운전 피드백, 경로 연동 알림 등)
3. **차량 상태 변화에 반응**하는 앱 (기어 P 전환, 도어 열림, 배터리 SOC, 경고등 등을 트리거로 쓰는 앱)

## 확인이 필요한 것

- [ ] **TTS·STT·FusedLocation을 공모전에서 쓸 수 있는가?** Playground 문서는 "준비 중", 공모전 사이트는 "사용 가능"으로 안내합니다. Playground에 로그인해 SDK 상태를 확인하고, 그래도 불분명하면 `appdevchallenge@hyundai-partners.com`에 문의합니다.
- [ ] **심사용 GitHub 계정**은 아직 공지되지 않았습니다. 공지사항을 확인합니다.
- [ ] **Playground 가입과 프로젝트 생성**: TTS·STT 서버 모드를 쓰려면 프로젝트의 클라이언트 ID와 시크릿이 필요합니다. 시크릿은 저장소에 올리지 않습니다.
- [ ] **팀 구성**: 시상 부문(대학생/일반)과 팀원 정보를 확정합니다.
